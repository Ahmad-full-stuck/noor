# نُور على Cloudflare — دليل التشغيل والأمان

آخر تحديث: 18 أكتوبر 2026

## رابط النسخة الجديدة

بعد نشر Worker مستقل من قائمة أصول صريحة، رابط التطبيق هو:

https://noor-secure.eva-store.workers.dev/

هذه النسخة منفصلة عن موقع Pages السابق، وتستخدم Worker واحداً للواجهة وواجهات API من المصدر نفسه حتى تكون ملفات الجلسة مرتبطة بالنطاق. تم إعداد قاعدة D1 مستقلة ومساحة KV مستقلة.

## أول تشغيل

1. افتح الرابط، واملأ البريد الإلكتروني الذي تريد استخدامه للحساب.
2. في شاشة التأسيس الأولى، أدخل رمز التهيئة لمرة واحدة الذي سيُسلّم لك خارج ملفات التطبيق، ثم أنشئ عبارة مرور قوية لا تقل عن 14 محرفاً وأكدها.
3. احفظ عبارة المرور في مدير كلمات مرور موثوق. وهي ليست مجرد كلمة مرور دخول: تُستخدم لاشتقاق مفتاح يفتح مفتاح التشفير الخاص بالبيانات.
4. بعد إنشاء حساب المالك الأول، يُرفض مسار تأسيس الحساب مجدداً. من قائمة «حسابي» تستطيع تغيير عبارة المرور الحالية إلى عبارة جديدة.
5. عند تسجيل الدخول من جهاز ثانٍ، استخدم البريد وعبارة المرور نفسيهما. سيُسحب آخر سجل مشفّر من الخادم.

**رمز التهيئة الأولي ليس مفتاح تشفير أو مفتاح API.** هو إذن مطالبة مؤقت يمنع أول زائر عابر من أخذ الحساب قبل إنشائه. لا يوجد مفتاح مزود خدمة أو مفتاح تشفير ثابت داخل JavaScript؛ التحقق من الحساب والجلسة يجريان على الخادم.

## التشفير والحفظ

- يُولّد مفتاح بيانات عشوائي AES-256-GCM في المتصفح.
- يُشتق مفتاح تغليف من عبارة مرور المستخدم باستخدام PBKDF2-HMAC-SHA-256 مع ملح عشوائي، ويُستخدم لتغليف مفتاح البيانات.
- قاعدة البيانات تستقبل لقطة مشفرة فقط؛ لا تخزن كلمة المرور الصريحة أو مفتاح البيانات مكشوفاً.
- الجلسة تستخدم رمزاً عشوائياً في Cookie بخصائص HttpOnly وSecure وSameSite=Strict، ويُحفظ تجزيد الرمز في D1.
- الحفظ السحابي يعتمد رقم مراجعة. إذا عدّل جهازان نسخة واحدة، تُرفض الكتابة ذات المراجعة القديمة ويُعرض اختيار صريح بدلاً من استبدال التعديلات بصمت.
- عندما ينقطع الاتصال، تبقى التعديلات في الذاكرة ويُحفظ سجل محلي مشفر بعد كل تعديل. عند عودة الاتصال تتم محاولة المزامنة أو يُعرض تعارض.
- كل مسارات تصدير النسخ الاحتياطية في الوضع السحابي (التحميل، الأرشفة الشاملة، ونسخة ما قبل إعادة ضبط المصنع) تصدّر غلافاً مشفّراً. رفض استيراد ملفات نسخ نصية غير مشفّرة افتراضياً، حتى لا تعيد بيانات واضحة إلى التخزين الآمن.
- ملفات المرفقات تُشفّر داخل المتصفح قبل الرفع. النسخة الحالية تستخدم KV مؤقتاً للملفات الخاصة حتى 20 ميغابايت للملف لأن R2 غير مفعّل بعد في الحساب.

## تنبيه بالغ الأهمية عن كلمة المرور

لا يوجد حالياً مفتاح استرداد مستقل أو استعادة تستطيع فك محتوى الخزنة عند فقدان عبارة المرور. إذا نُسيت العبارة، لا يستطيع الخادم استعادة محتوى البيانات المشفرة. تغيير العبارة من داخل النظام يتطلب العبارة الحالية، ثم يعيد تغليف مفتاح البيانات نفسه.

## الحالة الحالية والحدود

- تم نشر Worker باسم noor-secure (آخر deployment id: 03f7a62cb4d44ad5889907d5e8f7f78d)، وإعداد D1 ومساحة KV وربطهما.
- تم تضمين الأصول التالية فقط: واجهة التطبيق وCSS وملفات JavaScript التي تحتاجها. لم تُضمن قاعدة البيانات المحلية أو ملف seed أو مجلد uploads أو النسخ الاحتياطية في الحزمة المنشورة.
- فحوص GitHub Actions السابقة للدفعة شغّلت اختبارات قواعد المصادر وبناء القائمة المسموحة وفحوص صياغة JavaScript بنجاح.
- لم يكن فحص تفاعل المتصفح المباشر متاحاً في بيئة التنفيذ هذه، لذا ينبغي اعتبار أول تسجيل دخول ورفع ملف/مزامنة جهازين اختبار قبول عملياً لازماً قبل نقل بيانات شخصية مهمة.
- الحساب المهيأ حالياً هو حساب شخصي واحد؛ ليس منصة متعددة المستخدمين.
- لا تزال قاعدة البيانات المحلية والمرفقات متتبعة في المستودع العام أو تاريخ Git. عدم تضمينها في هذا الـWorker لا يزيل النسخ المنشورة سابقاً. يلزم تنظيف منفصل وحذر للتاريخ العام، مع نسخة احتياطية أولاً.
- لا تستخدم صفحات GitHub المنشورة أو نسخة محلية قديمة لإدخال بيانات حساسة. استخدم رابط Worker أعلاه بعد إنشاء الحساب، وتأكد من أن اتصال المتصفح HTTPS.

## تخزين الملفات مستقبلاً

R2 هو المكان الأنسب للتوسع إلى ملفات كبيرة. بعد تفعيل R2 من لوحة Cloudflare، يُنشأ bucket خاص ويُربط بالـWorker. لا تجعل الحاوية عامة ولا تُنشئ روابط دائمة مفتوحة؛ يجب أن يبقى فحص ملكية الملف في الـWorker، وأن تظل بايتات الملف مشفرة قبل التخزين.
