# نُور — نظام الحياة الشخصي

تطبيق ويب شخصي **أحادي المستخدم** لإدارة الحياة: مهام يومية، مؤقت تركيز (بومودورو)،
تدوين شامل، مشاريع، إحصائيات، نظرة، وأرشيف. واجهة عربية RTL بالكامل.

---

## بوابة الدخول والأمان

توجد في الواجهة بوابة رمزية تعمل داخل المتصفح لتقليل الوصول العرضي، لكنها **ليست نظام مصادقة حقيقياً** ولا تمنح الملفات المنشورة خصوصية. في GitHub Pages يستطيع الزائر الوصول مباشرة إلى أي ملف عام في المستودع، حتى إن لم يفتح الواجهة.

- لا تستخدم بيانات شخصية حقيقية أو ملفات خاصة في مستودع عام.
- لا تضع قاعدة البيانات `noor.db` أو ملفات `uploads/` أو النسخ الاحتياطية ضمن الملفات المنشورة.
- إضافة المسارات إلى `.gitignore` تمنع إضافتها مستقبلاً فقط؛ ولا تزيل الملفات المتتبعة حالياً أو نسخها من تاريخ Git.
- إذا سبق نشر ملفات شخصية، فالحل الكامل يحتاج إلى إزالة الملفات من الشجرة المنشورة وتنظيف تاريخ Git وفق خطوات GitHub الرسمية. احفظ نسخة محلية خاصة قبل أي إزالة.
- إذا كنت تحتاج إلى فتح نُور عن بُعد مع الاحتفاظ بالخصوصية، استخدم مصادقة على الخادم قبل إرسال البيانات؛ لا تعتمد على قفل JavaScript وحده.

خطة تطوير نُور ومركز التخطيط المقترح موجودة في [`docs/PRODUCT_BLUEPRINT_AR.md`](docs/PRODUCT_BLUEPRINT_AR.md).

## التشغيل (يوجد وضعان)

### الوضع 1 — سيرفر محلي بقاعدة بيانات في المجلد ⭐ (موصى به)
كل بياناتك تُحفظ تلقائياً داخل ملف **`noor.db`** في هذا المجلد نفسه، فيتحرك المجلد
كاملاً مع بياناته إلى أي جهاز. يكفي نقرة واحدة:

- **ويندوز**: انقر مزدوجاً على **`start.bat`**
- **ماك / لينكس**: شغّل `./start.sh` في الطرفية
- أو يدوياً: `node server.js`

يُفتح المتصفح تلقائياً على `http://127.0.0.1:4173/`. كل عملية (إضافة/إكمال/حذف)
تُحدّث قاعدة `noor.db` فوراً (مع نسخ احتياطية دورية في مجلد `backups/`).
للإيقاف: `Ctrl+C`.

> يتطلب **Node.js ≥ 22.5** (مثبّت مسبقاً لديك). لا حاجة لأي `npm install` —
> السيرفر صفري الاعتماديات ويستخدم وحدات Node المدمجة فقط.

### الوضع 2 — فتح مباشر (بلا سيرفر)
انقر مزدوجاً على **`index.html`** فيعمل فوراً عبر `localStorage` (بلا اتصال،
بلا تثبيت). لكن البيانات هنا داخل المتصفح لا داخل المجلد. يُكتشف غياب السيرفر
تلقائياً ويعمل التطبيق بسلاسة.

## أين تُحفظ البيانات؟

| الوضع | المكان |
|---|---|
| سيرفر محلي | ملف `noor.db` في المجلد + نسخ في `backups/` |
| فتح مباشر | `localStorage` داخل المتصفح |

في وضع السيرفر: بعد كل عملية تُدفع لقطة كاملة إلى `noor.db` (مع تأخير 1.5 ثانية
لتجميع التغييرات)، فقاعدة البيانات تتزامن مع أحدث حالتك دائماً.

## النسخ الاحتياطي والاستعادة

من **⚙ الإعدادات** داخل التطبيق:
- **↓ تحميل نسخة**: ينزّل ملف `noor-backup-YYYY-MM-DD.json` كاملاً.
- **استعادة**: تختار ملف نسخة فتُستبدل البيانات بمحتواه.

أنصح بتصدير نسخة أسبوعياً. في وضع السيرفر توجد أيضاً نسخ تلقائية في `backups/`.

## نقل المشروع لأي جهاز

انسخ المجلد كله (يشمل `noor.db`) إلى الجهاز الآخر، وتأكد من وجود Node ≥ 22.5،
ثم شغّل `start.bat`/`start.sh`. بياناتك تنتقل مع المجلد.

## هيكل المشروع

```
├─ index.html        نقطة الدخول (بوابة الرمز + الواجهة)
├─ js/lock.js        بوابة الدخول وحقن السكربتات بعد التحقق
├─ data/seed.json    البيانات المبدئية للنسخة المنشورة
├─ server.js         سيرفر محلي صفري الاعتماديات (node:http + node:sqlite)
├─ start.bat         تشغيل بنقرة واحدة (ويندوز)
├─ start.sh          تشغيل بنقرة واحدة (ماك/لينكس)
├─ package.json      (لا اعتماديات — فقط npm start اختياري)
├─ noor.db           قاعدة البيانات (تُنشأ تلقائياً)
├─ css/style.css     التصميم الكامل (عربي RTL)
├─ js/
│  ├─ store.js       طبقة البيانات (localStorage) + طبقة API محلية بديلة السيرفر
│  └─ app.js         الواجهة والتفاعل
├─ fonts/            خطوط محلية (Amiri + Tajawal)
├─ uploads/          المرفقات المرفوعة (صور/PDF)
└─ backups/          نسخ احتياطية تلقائية من قاعدة البيانات (غير مُرفع)
```

## النشر على GitHub Pages

النسخة المنشورة تعمل في **الوضع الثابت** (localStorage) بلا سيرفر:

1. المستودع عام إجبارياً — صفحات GitHub Pages لا تدعم المستودعات الخاصة.
2. عند الفتح، يكتشف `Bridge.detect()` غياب `/api/health` فيعمل التطبيق بسلاسة عبر
   `localStorage` (طبقة API محلية داخل `js/app.js`).
3. الروابط في `index.html` و`css/style.css` نسبية بالكامل، فتعمل تحت مسار فرعي
   `/<repo>/` بلا تعديل.

رابط النشر: `https://<username>.github.io/<repo>/`

## ملاحظات تقنية

- وضع `file://`: يكتشف التطبيق غياب السيرفر تلقائياً (`js/app.js` → `Bridge.detect`).
- الرفع: في وضع السيرفر يُحفظ على القرص في `uploads/`؛ وفي الفتح المباشر يُخزَّن
  كـ base64 داخل المتصفح (حتى 8MB).
- السيرفر يمنع اختراق المسار (path traversal) في الملفات والرفوعات.
- `apiFetch` في الوضع الثابت يسقط تلقائياً إلى المحاكاة المحلية (`_sendLocal`) عند
  غياب المسار في `_fetchLocal` — وهذا ما يُبقي صفحة المكتبة تعمل بلا خادم.

## التطوير الجاري: المزامنة الخاصة ومعالجة المصادر

العمل الحالي على الفرع `feat/integrated-planning-hub`، ولم يُدمج أو يُنشر بعد.

- [خطة إعداد المزامنة الخاصة](docs/PRIVATE_SYNC_SETUP_AR.md): اختيار Supabase مبدئياً، وسياسات الوصول، وخطة الترحيل الآمن.
- [ترحيل قاعدة البيانات وسياسات RLS](supabase/migrations/202610180001_private_sync.sql): أساس تقني للمراجعات ومنع الحفظ فوق إصدار أحدث وتخزين المرفقات في حاوية خاصة.
- [مركز التخطيط وخريطة المنتج](docs/PRODUCT_BLUEPRINT_AR.md).
- [قواعد تصنيف المصادر](js/source-rules.js): توحيد روابط الويب، وتصنيف أولي، وكشف تكرار، واقتراحات ربط تتطلب الموافقة.
- تشغيل اختبارات القواعد عبر `npm test`.

**تنبيه:** لم تُربط مصادقة Supabase أو المزامنة السحابية بواجهة الدخول والحفظ في التطبيق بعد. لا تضع مفتاح خدمة Supabase في JavaScript، ولا ترفع قاعدة بيانات المستخدم أو ملفاته إلى المستودع العام. وجود مخطط قاعدة البيانات في الفرع لا يعني أن حماية البيانات الحالية قد اكتملت.

## نسخة Cloudflare الآمنة

رابط النسخة الحالية على الفرع التطويري: **https://noor-secure.eva-store.workers.dev/**

- دليل النشر والأمان: [docs/CLOUDFLARE_DEPLOYMENT_AR.md](docs/CLOUDFLARE_DEPLOYMENT_AR.md)
- خدمة الحساب والجلسات والمزامنة: [cloudflare/worker.js](cloudflare/worker.js)
- مخطط D1: [cloudflare/migrations/0001_secure_vault.sql](cloudflare/migrations/0001_secure_vault.sql)
- تشفير المتصفح: [js/security.js](js/security.js)
- تصميم الزجاج والعمق الهادئ: [css/glass.css](css/glass.css)

النسخة الجديدة تستخدم Cloudflare Worker + D1 + KV. ملفات المرفقات تُشفّر في المتصفح قبل التخزين، لكن مساحة KV الحالية محدودة للملفات المشفرة حتى 20MB؛ لا تُرفع ملفات كبيرة قبل تفعيل R2. لا يوجد مفتاح خدمة أو مفتاح تشفير ثابت داخل JavaScript. أول تسجيل دخول يحتاج رمز تهيئة لمرة واحدة منفصلاً عن عبارة مرور حسابك، ثم يُغلق مسار إنشاء الحساب الأول بعد إنشاء المالك.

**قيود حالية:** لم يتمكن هذا التشغيل من إجراء اختبار تفاعل متصفح مباشر؛ يلزم اختبار تسجيل الحساب والمزامنة بين جهازين عملياً قبل نقل بيانات مهمة. كما أن فقدان عبارة المرور يعني فقدان القدرة على فك الخزنة لأن مفتاح استرداد منفصلاً لم يُضف بعد. لا تزال هناك ملفات تاريخية تتعلق بقاعدة البيانات والمرفقات في المستودع العام وتاريخ Git؛ نشر الـWorker بقائمة أصول محددة لا يزيل ما سبق نشره.
